# 预算：按任务累计（重跑不重置）

这条规则对应 README「设计约束」里的最后一条：**有成本上限**。

## 一句话

预算按**整条任务累计**算，不按单次运行算：同一个任务的每一次用例执行、每一次重跑，都从同一份额度里扣，重跑不会领到一份新预算。

## 怎么读这份文档

本文分两部分，别混着看：

- **规则**（「累计在什么之上」到「与 flaky 归因的关系」）：应当怎样记账、应当怎样停。这部分是**要求**，拦截能力大多数还没实现。
- **现状**（最后一节）：已经观察到什么证据、还差什么。**不要拿规则当已经生效的行为。**

## 术语：任务、用例执行、任务重跑

「尝试」这个词在仓库里已经被 `src/types.mjs` 占用了：`Attempt` 是**一条用例的一次执行**（`runner.repeat = N` 就是一个用例跑 N 次），不是整条任务跑一轮。为了避免两种「尝试」混在一起，本文只用下面三个词：

| 术语 | 含义 | 怎么记账 |
|---|---|---|
| **任务** | 一个 issue / PR 从发起到给出结论（跑通、超限放弃、人工收工）的整段工作 | 一本账 |
| **用例执行** | 一条用例跑一次；`runner.repeat = N` 就是 N 次 | 计入「执行次数」维度 |
| **任务重跑** | 同一个 issue / PR 再从头跑一遍（改一版重来、环境不对重来） | **不新建账**，继续扣同一本账 |

配置里没有 `runner.retry` 这种字段：`runner` 只认 `repeat`，写 `retry` 会被当成未知字段拒绝（见 [docs/config.md](docs/config.md)）。所以「重试」只有一种实现方式——任务重跑——而任务重跑不重置预算。

## 累计在什么之上

累计的载体是**一个任务**：既不是一次用例执行，也不是整个会话。

- **起算**：任务开始就起算，也就是**第一次花钱**的时候——读仓库、探查、规划、第一个用例执行，全都算在里面。不是「跑第一个用例」才起算：读代码和规划同样烧 token 和时间，把它们排除在额度外，等于给开销留了一个后门。
- **记账**：任务内每一次用例执行、每一次任务重跑，都记在同一本账上，不分「正常运行」和「为归因/调试而跑」。
- **清零**：任务结束才清零——跑通、超限放弃、人工收工，都算结束。**先出报告，再清零**：超限报告不能因为任务收尾而丢掉。
- **不共享**：同一会话里换到**另一个** issue / PR（另一个任务），才是新账，不继承上一个任务的余额。
- **重跑不重置**：同一个 issue / PR 的重跑仍然是同一个任务、同一本账。要更多预算，只能由人显式加，不能靠「重开一次」自动获得。

## 三个维度各自记账

任务开始前确定三个上限，各自独立累计、各自封顶：

| 维度 | 计数单位 | 上限从哪来 |
|---|---|---|
| 时间 | 毫秒 | 仓库配置 `limits.maxWallMs`，封顶整条任务的总时长（见 [docs/config.md](docs/config.md)） |
| token | token | **任务参数**，由发起方给定；仓库配置里没有 `maxTokens` 字段，写进 `limits` 会被配置校验拒绝 |
| 执行次数 | 用例执行次数（一条用例跑一次算一次） | 由仓库配置推导：`limits.maxCases` × `runner.repeat`，不是单独的配置字段 |

三个维度量纲不同，**不互相折算**，也不能拿一维的余额抵另一维：任一维度先触顶就停（例如 token 还剩很多，但执行次数到线，一样要停）。

## 为什么是累计

如果只封顶「一次运行」，那么一个永远跑不通的任务可以无限重跑：每次都在上限内，总量却早已失控。真正要防的不是某一次花得多，而是**在不断重跑里慢慢把钱烧完**。

下表**只看 token 这一维**，数字是编的，只为说明累计怎么记，不是运行证据：

| 运行 | 本次消耗 | 累计消耗 | 剩余（预算 2000） |
|---|---|---|---|
| 第 1 次 | 700 | 700 | 1300 |
| 第 2 次（任务重跑） | 600 | 1300 | 700 |
| 第 3 次（任务重跑） | 800 | 2100 | **超限，欠 100** |

关键点：

- **失败不退预算**。失败的运行一样花了时间和 token，一样计入累计。
- **重跑不是免费的**。重跑要重新读上下文、重新跑，成本往往比第一次更高。
- **一次运行可能越过上限**。上表第 3 次开跑时还剩 700，跑完花了 800，越了 100。能不能越过，取决于开跑前估不估得出成本（见下节）；越过了就立即停，并在报告里写出欠额，不装作没发生。

## 触顶怎么停

两种都算「被预算拦住」，报告里的标签统一：

1. **触顶**：任一维度到达上限，立即停止——不再发起新的用例执行，也不再发起任务重跑，直接出报告。
2. **预估不足未启动**：能事前估算的，开跑前先估；预估消耗超过剩余额度就不启动。这种情况下停下来时**剩余额度可以大于 0**，所以报告不能一律写「预算耗尽」。

要求：超限之后不做「再试最后一次」，也不再靠重跑试错。反复重跑要花的是同一本账上的钱，账不会因为「我再试一下」而变宽。

## 超限之后

超限时输出（这就是「超限报告」的最低内容）：

- 每个维度各自的**累计消耗与上限**（时间、token、执行次数分别列出，不合并成一个数）；
- **停在哪一步**：第几次任务重跑、当时在做什么（读代码 / 规划 / 跑用例 / 归因重跑）；
- **已有的中间结果**：哪些用例跑通了、哪些失败了及证据；没覆盖的部分写明「因预算受限未覆盖」；
- **欠额**（如果有）：越过了多少，例如 token 超 100；
- **未归因清单**（如果有，见下节）。

这些信息交给人工判断是加预算还是收工——工具不替人做这个决定。

## 与 flaky 归因的关系

README 要求 flaky 用例「重跑若干次」才能归因，归因重跑同样要花钱。两条规则叠加时的边界：

- **重跑照常记账**。为归因而做的每一次用例执行都计入执行次数与累计消耗，不因为「这是归因」而免费，也不另开一本账。
- **触顶就停归因**。归因所需的重跑如果到达上限，立即停止重跑，不因为「还差两次就能确认」而续跑。
- **不放宽上限去凑次数**。不允许为了凑够重跑次数临时抬高上限；要更多次数得由人显式加预算。

### 「未归因」怎么表示

「未归因」只是**报告级的标签**，不是 `RunStatus` 的第五个值。`src/types.mjs` 把 `RunStatus` 钉死为 `passed | failed | flaky | error`，`tests/types.test.mjs` 也断言了这一组，新增状态会直接破坏共享契约。

落到产物上：

- 每条 `RunResult` 仍按实际执行结果给出四值之一，`attempts` 原样保留（跑了几次、每次什么结果、为什么停）；
- 报告里**另开一栏**「未归因（预算受限）」，列出这些用例的 id、已有的执行结果与证据，并注明「重跑次数不足，未完成归因」；
- 「未归因」的用例既**不并入「稳定失败」**，也**不当作「通过」**，不静默丢弃；
- 要把「未归因」变成机读字段，属于契约变更（会动到 `RunStatus` 与契约测试），另开 issue 讨论，不在这份文档里偷偷加。

## 现状：记账有证据，拦截没有

规则和现状必须分开说。到目前为止，**记账**被观察到过，**拦截**没有被观察到过。

证据来自 issue #43 的一次任务（预算 2000 token，`Verify: false`）。任务没有跑通，监督者留下了两条评论：

| 时间 | 报告消耗 | 同一份预算 | 监督者结论 |
|---|---|---|---|
| 09:53:07 | 16.1k token | 2000 | over its 2k budget. Needs a person. |
| 09:54:11 | 13.0k token | 2000 | over its 2k budget. Needs a person. |

从这两条数据能得出：

- **证明了的**：账是按任务算的，没有在重跑时换一份新预算——同一个 issue 的第二次运行仍然对着同一个 2k 预算被判定超限，重跑没有把额度变宽。
- **没证明的**：预算拦得住任务。两次运行分别超到预算的 8 倍和 6.5 倍之后，任务仍在继续，最后是**人叫停**的，不是工具停的。这次运行也没有留下上节要求的超限报告：PR 描述里只有 run id 和 `Acceptance checks: Verify: false`，没有每维度的消耗/上限、没有停止点、没有中间结果。

结论：

- 「累计记账」有证据；「到线即停」「不在超限后继续试错」**尚不成立**，本文这两条是待实现的要求。
- 在拦截真正生效、并留下一次「接近上限，且记录了实际花费与停止点」的运行之前，不能宣称预算机制已经能自己拦住任务。注意 [docs/money-budget-demo.md](docs/money-budget-demo.md) 已经明确说过：那份演示证明的是失败被如实上报，不是预算拦截能力本身。
- 拦截落地后，把那次运行的报告回填到本节；在那之前，本节如实写着「没做到」。
