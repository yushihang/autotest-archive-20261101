# 配置文件说明

> **状态：规划中的配置契约，尚未实现。** 仓库里目前还没有配置加载模块（见 README「现状」），
> 本文先定下字段与校验规则，实现落地时须与本文一致。

autotest 的配置是一份 JSON 文件，可直接复制的示例见仓库根目录的
[`autotest.config.example.json`](../autotest.config.example.json)：

```bash
cp autotest.config.example.json autotest.config.json
```

规划中的读取入口是 `loadConfig(path)`（路径相对当前工作目录解析），校验和规范化一次完成。
下游模块拿到的是规范化后的值：`target.baseUrl` 不带结尾 `/`、`testsDir` 一定带结尾 `/`、
`target.routes` 已去重。字段和规则要变时先改本文，再改实现。

## 顶层结构

```json
{
  "target": {
    "baseUrl": "http://127.0.0.1:4173",
    "routes": ["/", "/login", "/cart"]
  },
  "limits": {
    "maxCases": 20,
    "maxWallMs": 300000,
    "maxSteps": 12
  },
  "runner": {
    "repeat": 2
  },
  "output": {
    "dir": "autotest-output"
  },
  "testsDir": "test/"
}
```

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---|---|---|
| [`target`](#target) | object | 是 | 无 | 被测应用的地址与路由 |
| [`limits`](#limits) | object | 是 | 无 | 成本上限：用例数、总时长、单例步数（token / 金额预算另见 [`limits`](#limits)） |
| [`runner`](#runner) | object | 是 | 无 | 执行器行为 |
| [`output`](#output) | object | 否 | 见下文 | 报告、截图、inventory 的落盘目录 |
| [`testsDir`](#testsdir) | string | 否 | `"test/"` | 生成测试文件的落盘目录 |

顶层只允许出现上表中的 5 个字段。任何层级出现未知字段都会报错（例如把 `testsDir` 写成
`testsdir`），不会静默回落默认值。

## `target`

被测应用。必填对象，只允许 `baseUrl` 和 `routes` 两个字段。

注意：`baseUrl` 和 `routes` **不是顶层字段**，必须写在 `target` 下；直接放在顶层会被判为未知字段。

| 子字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `baseUrl` | string | 是 | 无 | 站点根地址 |
| `routes` | string[] | 是 | 无 | 要探测的路由 |

### `target.baseUrl`

| 项 | 说明 |
|---|---|
| 类型 | string |
| 必填 | 是 |
| 默认值 | 无 |
| 示例 | `"http://127.0.0.1:4173"` |

校验规则：

- 必须是合法 URL：带协议和主机名，能被标准 URL 解析器接受。
- 协议只能是 `http:` 或 `https:`，`file:`、`ftp:` 等一律拒绝。
- 不能带查询串（`?`）或 hash（`#`）——具体路由写在 `target.routes` 里。
- 允许带路径前缀，如 `"https://example.com/app"`。
- 前后空白会被去掉；结果统一去掉结尾 `/`，拼接路由时只在一处加。
- 只写 `127.0.0.1:4173` 不合法，必须补 `http://`。

### `target.routes`

| 项 | 说明 |
|---|---|
| 类型 | string[] |
| 必填 | 是 |
| 默认值 | 无 |
| 示例 | `["/", "/login", "/todos?filter=done"]` |

校验规则：

- 必须是数组，且至少 1 项；空数组报「不能是空数组，至少写一条路由」。
- 每一项必须是字符串；空白会被去掉，去掉后不能为空字符串。
- 必须以 `/` 开头，因此不能写完整 URL（`https://example.com/login` 应写成 `/login`）。
- 不能包含 `#`；查询串允许，如 `"/todos?filter=done"`。
- 末尾 `/` 会被去掉（根路径 `/` 除外）；去重后保留首次出现的顺序。
- 某一项出错时，错误字段路径精确到下标，如 `target.routes[0]`。

## `limits`

成本上限：到限必须停并如实报告，不允许无限试错。必填对象，只允许下面 3 个字段，且**三个都必填**，没有默认值。

三种上限的作用范围不同：`maxWallMs`（总时长）和 `maxCases`（用例数）是整轮上限，任一到顶即中止本次任务；
`maxSteps` 是**单条用例**的上限，超限的那条用例整条不执行（砍掉后半段会让断言失去意义），但其后
的用例继续跑——一条异常长的用例不该把整轮覆盖全砍掉，跳过记录会写进执行报告。

这三个字段只封顶「这次跑多少」（用例数、时间、单例步数）；token 和金额预算不写在仓库配置里，
来源见本节末尾的「与 README 的成本上限如何对应」。

| 子字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `maxCases` | integer | 是 | 无 | 单次任务最多生成多少条用例 |
| `maxWallMs` | integer | 是 | 无 | 单次任务的总时长上限，毫秒 |
| `maxSteps` | integer | 是 | 无 | 单条用例最多多少步；超限的用例整条跳过，不影响其他用例 |

三者共用同一套校验：

- 必须是 JSON 数字且有限（`NaN` / `Infinity` 不是合法 JSON，无法通过解析）。
- 必须是整数，小数会报「必须是整数」。
- 必须 `>= 1`，`0` 和负数拒绝。
- 没有上限值，但设得过大等于放弃兜底，按实际任务规模填写。

### 与 README 的成本上限如何对应

README 承诺「单次任务的时间、token、执行次数都要封顶」，各自的来源是：

| README 的上限 | 由什么决定 |
|---|---|
| 时间 | `limits.maxWallMs` |
| 执行次数 | `limits.maxCases` × `runner.repeat`（每条用例最多 `limits.maxSteps` 步） |
| token / 金额预算 | 不在仓库配置里：发起任务时由调用方给定，随任务参数传入 |

仓库配置只回答「这次跑多少」，预算只回答「这次最多花多少」；两者任一先到即停并如实报告。
把预算放在任务参数而不是仓库配置里，是因为上限该由发起者定，被测试仓库不能给自己放宽，
同一份配置也能在不同预算下复用。

## `runner`

执行器行为。必填对象，当前只允许 `repeat` 一个字段。

| 子字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `repeat` | integer | 是 | 无 | 每条用例重复执行几次，用于判定 flaky |

校验规则：

- 必须是整数且 `>= 1`。
- `1` 表示不重复，失败即失败；`2` 及以上时，多次结果不一致的用例会被标记为 flaky。
- 目前没有默认值，必须显式写；写 `0` 会报「必须 >= 1」。

## `output`

产物目录。可选对象，只允许 `dir` 一个字段；整段省略时 `dir` 取默认值。

| 子字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `dir` | string | 否 | `"autotest-output"` | 报告、截图、inventory 的落盘目录 |

校验规则：

- `output` 一旦出现就必须是对象；`"output": {}` 合法，等价于全部取默认值。
- `dir` 必须是字符串，去掉前后空白后不能为空。
- 必须是仓库内的相对路径：拒绝绝对路径（`/...`、`\...`、`C:...`）。
- 不能包含 `..` 段，不能是根目录或当前目录（`""`、`.`、`./`）。
- 开头的 `./` 会被去掉，结尾的 `/` 也会被去掉；规范化后不带结尾 `/`。

## `testsDir`

生成的测试文件写到哪个目录。可选，默认 `"test/"`。

| 项 | 说明 |
|---|---|
| 类型 | string |
| 必填 | 否 |
| 默认值 | `"test/"` |
| 示例 | `"tests/autotest/"` |

校验规则：

- 与 `output.dir` 相同的目录规则：只接受仓库内相对路径，拒绝绝对路径、`..`、根目录 / 当前目录。
- 开头的 `./` 被去掉；结尾 `/` 会被统一补上，因此规范化结果一定以 `/` 结尾。
- 目录不存在时由下游创建；工具边界是「只加测试文件、不碰别处」，所以不会写到仓库外。
- 该目录用于自动生成的测试，不要指向业务源码目录。

## 错误行为

配置在任务开始前一次性校验。读不到文件、JSON 语法错误、字段缺失、类型不对、取值越界或出现未知字段，
都会抛出 `ConfigError`（规划中的错误类型），不会带着半份配置继续跑。错误信息格式为：

```
配置错误 [字段路径]：原因
```

字段路径是点路径，例如：

- `limits.maxCases` —— 缺字段或不是正整数
- `runner.repeat` —— 小于 1
- `target.routes[0]` —— 第一条路由不是以 `/` 开头的字符串
- `testsDir` —— 写成绝对路径或包含 `..`

未知字段同样报错，例如顶层多写 `testDir` 会提示顶层只支持
`target / limits / runner / output / testsDir`。
